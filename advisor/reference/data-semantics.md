# 数据口径与已知陷阱

本文记录在 `flight_monitor.db` 上做购票决策时必须知道的口径，全部在真实数据上验证过。

## 1. 基础事实

| 项 | 值（2026-09-16 实测） |
|---|---|
| 表 | `flight_prices` 71,000+ 行 / 181 批次 / `price_alerts` / `monitor_log` |
| 抓取时间跨度 | 2026-06-30 → 2026-09-16 |
| 起飞日跨度 | 2026-06-30 → 2026-10-17 |
| 主力航线 | `bjs->jjn` 35,909 行 / 109 起飞日；`jjn->bjs` 30,859 行 / 108 起飞日 |
| 稀疏航线 | `bjs->xmn` 4,724 行 / 9 起飞日；`hsn`/`ngb` 各 ~60 行 / 1 起飞日 |

观察期覆盖暑期 + 中秋 + 国庆前夜，**不含冬季/春运**。绝对金额需按季节重新校准，
相对规律（提前量、航司/机场分层）可平移。

`price` 的口径是**抓取时该航班的最低可订价**，不是某个具体舱位的票价。

## 2. 七个已验证的陷阱

### 2.1 `lead` 上限只有约 41 天

爬虫只看未来 `MONITOR_DAYS_AHEAD=30` 天，告警航线会提前更久开始盯。实测全库 `lead` 最大 41。
所以 `common.LEAD_BIN_ORDER` 里的 `"45天前"` 桶**永远是空的**——那个桶名是误导。

### 2.2 粗桶 `lead_bin` 让分位数退化

`lead_bin` 的桶宽太大（`1-3天`、`21-29天`…）。实测后果：

- 北京→泉州在 `"1-3天"` 桶内，**每一个起飞日的 P25/P50/P75 都是完全相同的 357.5 / 475.0 / 560.0**；
- 长提前量桶样本极少：`"30-44天"` 桶只有 **n=6**，却照样输出三个分位数当基准。

**所以决策路径完全不经过 `lead_bin`**，改用围绕实际 `lead` 的滑窗（见 §3）。
`lead_bin` 只在卡片里作对照保留。

### 2.3 "当前价"不能用全局最后一批当锚点

原 §3 表用 `df[df.crawl_dt == 全局最后一批]` 取"现在能买到什么"。
但**告警优先爬取**会让各航线的最后一批时间不同。实测：

> 全局最后一批是 `2026-09-16 20:17:02`，但北京→泉州该日期的末次观测是 `19:27:38`——
> **北京→泉州 2026-10-17 整条不在最后一批里，会被静默丢弃。**

正确做法：按 `(航线, 起飞日)` **各自**取最新一次观测。

### 2.4 长假污染同期基准

监控始终向前看约 30 天，所以"提前 28–34 天"这个窗口里的历史起飞日，
必然是爬取日之后约 30 天的那些。实测：

| lead 窗口 | 基线里 10 月（国庆）起飞日占比 |
|---|---|
| `[28,34]` | **15/68 = 22%** |
| `[14,20]` | 6/85 = 7% |
| `[7,13]` | **0%** |

国庆是全窗口最贵的时段，会把长提前量的 P25/P50/P75 整体抬高，
让国庆前后的价格显得"正常"。core 用数据驱动判据标出高峰日期
（某起飞日的 floor 中位 > 全线中位 × 1.35），并额外给一版剔除高峰后的分位。

### 2.5 参照集范围能让分位摆动 20+ 个百分点

同一个价格，换不同历史范围做基准，分位能差很多。实测北京→泉州 2026-09-22：

```
±7天 66.3%   ±14天 57.9%   ±30天 46.2%   全部历史 29.8%
```

原因：6–7 月暑期票价系统性高于 9 月。**没有 scope 校正，分位就是季节的伪影。**
core 默认取最贴近的同期参照，并把摆动幅度显式报出来、据此下调置信度。

### 2.6 等待胜率有幸存者偏差

只对"活下来的航班"统计涨跌，会严重高估等待的收益。实测北京→泉州：

```
L=21 → t=7   配对 520  消失 19.0%  跌 34.0% 平 11.9% 涨 54.0%  中位 +70
L=14 → t=0   配对 207  消失 67.7%  跌  6.8% 平  1.4% 涨 91.8%  中位 +500
L= 7 → t=0   配对 232  消失 63.3%  跌  6.9% 平  5.6% 涨 87.5%  中位 +420
```

"等到起飞当天涨 91.8%"是在**只剩 32% 的航班还能买到**的前提下算出来的。
所以 `disappear_rate` 必须与涨跌率并列展示——等待的真实代价不是"涨多少"，
而是"可能根本买不到原来那班"。

### 2.7 价格分布的两类污染

| 污染 | 实测 | 处理 |
|---|---|---|
| **平台价** | ¥520 占泉州→北京快照 **10.3%**，次高档仅 4.7%（突出度 2.2×） | 标 `PLATFORM_PRICE`，说明"航司固定档位，非促销，也不代表便宜" |
| **全价舱跳变** | 价格 ≥2190 的快照 **80% 落在 lead≤3**（基线 12%，富集 6.9×） | 标 `FULL_FARE_JUMP`，说明"仅剩全价舱，不计入普通涨价" |

注意：早期 EDA 文档记的"500/520 占 13.4%""≥2000 有 59% 在 lead≤3"是 6/30–9/3 快照的数，
现在已漂到 10.3% / 80%。**这本身就说明所有这类比例都必须实时算，不能硬编码。**

### 2.8 北京→厦门是页面级起价，不可用

EDA 00 §4b 的判据（**同批次内 ≥5 个航班完全同价**，注意不是"所有航班同价"）：

| 航线 | 同价共振组 | 单航班单批次价格档数中位 |
|---|---|---|
| `bjs->xmn` | **100** | **2.0** ← 疑似页面"¥xxx 起"占位价 |
| `bjs->jjn` | 1 | 9.0 |
| `jjn->bjs` | 1 | 9.0 |

**"价格档数中位"是比共振组更干净的判别器**（2.0 vs 9.0）。
core 两条判据都用，命中即拒绝给该航线出分位。

> 踩坑记录：最初把判据写成"同批次**所有**航班同价"，实测恒为 0 组；
> 改成"**≥5 个航班**同价"后才复现出 EDA 的 100 组。

## 3. 分位算法

```
样本 = 同航线、其它起飞日、lead ∈ [L-w, L+w]、|起飞日 − 目标日| ≤ scope 的每日 floor
分位 = 100 × (严格小于现价的样本数 + 0.5 × 相等的样本数) / 样本数
```

- 窗口 `w` 从 ±3 起，样本不够依次放宽到 5 / 7 / 10
- 时间范围 `scope` 从 ±14 天起，依次放宽到 30 / 62 / 全历史
- 只取**最窄的满足置信门槛**的组合；门槛：high = n≥60 且 ≥8 个起飞日，
  medium = n≥25 且 ≥5，low = n≥12 且 ≥3
- 低于 low → **拒绝给分位**，只回报"能说什么"
- 用留一法（leave-one-out）排除目标起飞日自己

## 4. 运行环境

**任何装了 `pandas` / `numpy` 的 Python 都行**，不必是某个特定环境——
advisor 只用到 pandas / numpy / sqlite3。找解释器的稳妥做法见
`advisor/SKILL.md` §0 步骤 2 的 `find_py`（顺序同 `run_dashboard.bat`：
`CONDA_PREFIX` → conda 根 → 常见安装位置 → PATH，且每一档都真 `import` 一次才认）。

`cli.py` 会自动检测依赖缺失并给出可照做的提示，不会只抛 `ImportError`。

Windows 控制台默认 GBK，输出含 `¥` / `→` / `≤` 会 `UnicodeEncodeError`。
`cli.py` 在启动时强制 `sys.stdout.reconfigure(encoding="utf-8")`；
在 bash 里组合调用时另需 `export PYTHONIOENCODING=utf-8`。

## 5. 缓存

`advisor/cache/*.pkl`，key 含 DB 的 `mtime_ns` + `size` + `as_of` + 航线，
DB 一变自动失效。缓存只存派生帧（grid / floor / traj / 特征化后的 df），
**永远只是加速，不是真相来源**——读取失败就重算。冷跑约 11s，热跑约 1.3s。

⚠️ **缓存会自我清理**：key 里含 DB 的 mtime，所以爬虫每写一次库就会产生一批新文件。
`_cache_evict` 每次写入后删掉同一 `(route, as_of)` 下的旧版本，`_cache_cap` 再兜底
只保留最近 12 个文件。**没有这层清理的话，跑一天就能涨到 389MB**（14 份完整
DataFrame 副本占 224MB）——这是实测踩过的坑，别去掉这两个函数。

稳态约 60–70MB。整个目录可以随时 `rm -rf advisor/cache/*`，只是下次冷跑。
